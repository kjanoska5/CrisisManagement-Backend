# CONTRIBUTING

## Strategia branchowania (GitHub Flow)
- `main` zawiera zawsze działającą wersję kodu.
- Każde zadanie realizujemy na osobnym branchu: `numer_issue-krotki-opis` (np. `7-zgloszenie-zdarzenia`).
- Po zakończeniu pracy otwieramy Pull Request do `main`.
- PR wymaga krótkiego review drugiej osoby przed mergem.
- W opisie PR dodajemy `Closes #numer_issue`, żeby issue zamykało się automatycznie.
- Po zmergowaniu branch usuwamy.

## Commity
Piszemy commity małe i opisowe, np.: `dodaj formularz zgłaszania zdarzenia (#7)`

## Code review
Przed mergem druga osoba przegląda zmiany. W razie wątpliwości — rozmawiamy zamiast zgadywać.
